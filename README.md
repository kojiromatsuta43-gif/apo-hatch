# 【フォーム＆メール】アポハッチくん

問い合わせフォームとメールへの営業送信を自動化するツールです。各自のパソコンにインストールして使います（外部のサーバーは使いません。送信もデータの保存も、そのパソコンの中で行います）。

使い方は、起動後の画面上部にある **「ご利用ガイド」** に手順とよくある質問をまとめています。初めての方はそちらから進めてください。

開発する方は `CLAUDE.md` を先に読んでください。

## はじめて使う（インストール）

### かんたんな方法（おすすめ・ターミナル不要）

1. **Node.js（LTS）** を入れる → https://nodejs.org/
2. zip を解凍する
3. そのフォルダの中の
   - **Windows**: 「**インストール（最初に1回）.bat**」をダブルクリック（部品の用意からデスクトップのショートカット作成までやります）
   - **Mac**: 「**アポハッチくん起動.command**」をダブルクリック（初回は部品の用意から行います）。アイコンから開きたい場合は「**アポハッチくん.app**」を右クリック →「開く」→「開く」（最初の1回だけ確認が出ます）
4. 自動でブラウザが開き、ターミナルに表示された管理者アカウントでログイン

2回目からは、デスクトップのショートカット（Windows）／「アポハッチくん起動.command」か「アポハッチくん.app」（Mac）をダブルクリックするだけです。
黒い画面は閉じないでください（閉じると送信も止まります）。

### これまでの方法（コマンドで操作する）

1. **Node.js 22（LTS）** を入れる → https://nodejs.org/ （「LTS」をダウンロードしてインストール）
2. zip を解凍し、ターミナル（Windows は PowerShell、Mac はターミナル）でそのフォルダに移動
3. 下の3行を順に実行（初回は数分かかります）

```bash
npm install
npx playwright install chromium     # 初回のみ（フォーム操作用のブラウザ本体）
npm start                            # → http://localhost:3210
```

※ `npx playwright install chromium` が「Playwright does not support chromium on mac13」などで失敗する古いOS（macOS 13 以前など）でも、**Google Chrome（または Microsoft Edge）が入っていれば自動でそちらを使う**ので、そのまま `npm start` で使えます。

4. ブラウザで http://localhost:3210 を開き、ターミナルに表示された管理者アカウントでログイン
5. 画面上部の「ご利用ガイド」に沿って、送信者の登録 → キャンペーン作成 → リスト取り込み → 開始

止めるときはターミナルで Ctrl+C（送信中の会社があれば、送り終わってから止まります）。データは `data/` フォルダに残ります。

## ログイン

初回起動すると、ターミナルに管理者アカウントが1度だけ表示されます。

```
============================================================
  最初の管理者アカウントを作りました。控えておいてください。
  ログインID : admin
  パスワード : xxxxxxxxxxxx
============================================================
```

このID・パスワードでログインし、画面の指示に従ってパスワードを変更してください。メンバーのアカウントは「ユーザー管理」から発行できます（一般ユーザーには自分のデータだけが見えます）。

初期パスワードを自分で決めたい場合は、初回起動時だけ環境変数で指定できます:

```bash
ADMIN_USER=admin ADMIN_PASSWORD=好きなパスワード npm start
```

同じログインIDで15分に5回パスワードを間違えると、しばらくログインできなくなります。

## 使う前に知っておいてほしいこと

- **メールの送りすぎに注意**：短時間に大量に送ると、Gmail のアカウントが一時停止されます。作ったばかりのアカウントは1日50〜100通から始め、日中に少しずつ送ってください。停止やログイン拒否を検知すると、アポハッチくんはメール送信を自動で一時停止します（残りの会社は「待機」のまま）。
- **営業メールの法律上の表示**：特定電子メール法により、営業メールには送信者の名称・住所・配信停止の連絡先の表示が必要です。送信者の住所が未登録だとメールは送られません。メールの末尾には「メール配信停止」リンクが自動で入ります。
- **受信箱の読み取り**：送信者プロフィールで「受信箱を読んで…自動で記録する」をオンにすると（初期値オン）、送信用メールの受信箱を15分ごとに読み、送った会社からの返信（返信あり／アポ／断り）と、届かなかったメールを自動で記録します。読み取りはこのパソコンの中だけで行います。個人のメールと兼用している場合はオフにしてください。
- **パソコンのスリープ**：送信はこのパソコンの中で動くため、スリープ・ふたを閉じる・アプリの終了で止まります（起動すると続きから再開）。
- **他のパソコンから開く**：同じWi-Fi・社内ネットワークの人は、「ユーザー管理」に表示されるURLで開けます。アドレス欄の localhost のリンクは他のパソコンでは開けません。カフェ等の共用Wi-Fiでは、同じネットワークの他人からもログイン画面が見える点に注意してください。
- **パスワード類の保存**：Gmail のアプリパスワードと AI の APIキーは、このパソコンの `data/` 内に保存されます（暗号化はしていません）。共用パソコンでは使わないでください。
- **除外リストはパソコンごと**：別のメンバーのアポハッチくんとは共有されません。チームで使う場合は、断りの会社を定期的に共有してください。
- **初期文面**：新しいキャンペーンの本文・件名には【ここに…】の書き換え箇所があり、書き換えないと送信できません。

## AI の設定（任意）

テンプレートでの送信は無料で、AI は不要です。AI で文面を個別化する場合は、**画面の「設定」から APIキーを登録**します（管理者のみ）。料金の目安・取得手順も設定画面に書いてあります。キーはこのパソコンの `data/` 内にだけ保存されます。

環境変数でも渡せます（設定画面が優先）:

```bash
ANTHROPIC_API_KEY=sk-... npm start     # Claude
GEMINI_API_KEY=...       npm start     # Gemini
```

## 画面の案内

- **はじめの設定**（`/setup`）… 送信者の登録からリスト取り込みまで6ステップで案内します
- **ホーム**（`/`）… 今日・今月の送信数、アポ、要対応、次にやることを1画面に
- **要対応**（`/todo`）… 自動で送れなかった会社（画像認証・失敗・要確認・フォーム無し）を1画面で処理
- **送信数と分析**（`/stats`）… 日別・月別の送信数、業種別／都道府県別／時間帯別の反応率、送れなかった理由ランキング
- **週次レポート**（`/report`）… 前週比・アポ一覧。印刷してそのまま報告に使えます
- **動作チェック**（`/health`）… 動かない原因の切り分け、自動起動・自動更新・バックアップ・診断ファイル
- **エラーログ**（`/logs`）… 直近500件の出来事（黒い画面を閉じても追えます）

## チームで使う

- **除外リストの共有**（取り込み）… Googleスプレッドシートを1つ決めて、全員が同じURLを登録（1日1回自動）
- **送信済み・除外の双方向共有**… 「除外リスト」画面の「チームで共有する」に、読み取り用のシートURLと、書き込み用の Apps Script URL を登録すると、
  誰かが送った会社には他のメンバーが送らなくなります（取り込み時と送信直前に確認）。Apps Script のコードは画面からコピーできます

## ライセンス（配布元の作業）

他社に渡すときの期限・台数の管理に使えます（既定では送信を止めません）。

```bash
node scripts/license.mjs --init                               # 最初の1回だけ。鍵を作り、公開鍵を src/license.ts に貼る
npm run license -- --to "株式会社サンプル" --days 365 --seats 3  # キーを発行して相手に渡す
```

相手は「設定」画面にキーを貼ります。「ライセンスが無い・期限切れのときは1日50件までに制限する」はチェックで切り替えられます（既定はオフ）。
※ ソースごと配る仕組みのため、これはコピー防止ではなく期限・台数の管理のためのものです。

## 守っていること

- 「営業お断り」文言を検知したらスキップし、そのドメインを除外リストに自動登録（キャンペーン設定で「送る」に変更可・非推奨）
- 目に見える CAPTCHA（reCAPTCHA v2 / hCaptcha / Turnstile / 画像認証）があればスキップ。突破はしない
- 同じ会社には再送禁止期間（既定90日・キャンペーンごとに変更可）は再送しない（全キャンペーン横断）。グループにしたキャンペーン同士でも重ねて送らない
- 官公庁・自治体・学校のドメインは既定で除外
- 送ったか判断できなかった会社は「失敗（要確認）」にして、自動では送り直さない（二重送信を防ぐため）
- 配信停止・断りの返信・宛先不明で戻ってきたアドレスには、以後送らない
- 送信結果はスクリーンショット付きで保存

## 更新版を配る（配布元の作業）

このリポジトリが開発の正であり、配布元でもあります。配布した各PCは
`https://raw.githubusercontent.com/kojiromatsuta43-gif/apo-hatch/main/release.json` を見に来ます。

**更新版を出す手順**

```bash
git pull                              # 先に他の人の変更を取り込む
npx tsc --noEmit && npm test          # 型チェックと送信の通しテスト
npm version patch                     # 0.3.1 → 0.3.2
npm run release -- "直した内容を一言"    # release.json を書き出す（この文言が利用者の画面に出ます）
git add -A && git commit -m "アポハッチくん v0.3.2" && git push
```

**先行版として出す**こともできます（自分たちのPCだけで先に試し、問題がなければ安定版にする）。

```bash
npm run release -- --beta "試したい変更"   # 先行版（アップデート画面で「先行版」を選んだ端末にだけ届く）
npm run release -- "問題なかったので全員へ" # 安定版（全端末に届く）
```

`git push` はこの1回だけです。これで各PCの「アップデート」画面に新しい版が出ます。

**バージョンを上げずに push した場合**は、コードはGitHubに入りますが誰にも配られません。
開発中の細かい修正はそれでよく、区切りがついたところでリリースする、という使い分けで構いません。

配布元を変える場合は `update.json` の `manifest_url` を書き換えてから配り直してください。
